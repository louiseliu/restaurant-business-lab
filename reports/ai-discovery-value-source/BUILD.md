## 官方复建

需要Python 3、官方Node和当前Data analytics插件。在获准环境中定位它们，不在本目录写个人绝对路径。

1. 将本目录放在新的 `PRODUCTION_DIR/source`。不要覆盖已有用户改动。
2. 运行 `python source/build_standalone.py PRODUCTION_DIR NODE DATA_PLUGIN_ROOT`。生成器先核首提commit、时间、冻结标记与正文/来源哈希；新项目使用官方 `prepare-data-app.mjs --surface report` 和受检快照，保留准备器分配的稳定报告ID。读取生成的AGENTS和匹配组件参考后继续维护。
3. 安装器仅写作者内容和数据。若已有正文、图文、query、reader或样式与输入不同，则拒绝覆盖；多文章query与缺失身份也拒绝。
4. 脱敏测试及只读扫描通过后设 `buildStatus=complete`，运行官方 `data-app.mjs prepare`、`build --separate-data` 与 `export-offline`。不启用替代运行时，不修改受保护文件。子进程移除可选会话标记变量。
5. 导出在官方允许的 `.data-app-offline/exports/` 下，再复制为 `PRODUCTION_DIR/ai-discovery-value.html`。该大文件仅本地保留，不属于本源码归档。
6. `test_standalone.py` 实际检查冻结全文、来源、双图行和来源作用域、compiled JSON、分离数据与manifest、官方文件和脱敏模式。`test_authoring_guard.py` 使用临时副本测试八项防覆盖行为。

本轮沿用最新64篇门户的官方Data构建方法，但没有修改门户或旧文章。最新完整门户基线仍64研究/84全文/2样板、AI42、131 queries，Q-Smart同篇新修订也尚未由本步骤纳入。本篇为第65篇研究、AI43，单篇本地构建完成不代表门户更新。
