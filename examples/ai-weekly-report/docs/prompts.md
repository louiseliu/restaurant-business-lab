# 可复制操作提示词（局部模板，未安装为 Skill）

用途：计算后再让 AI 组织文字。**本包是当前 AI 助手实际读结果后编写，不是以下提示词通过外部 API 执行的录像或测试。** Python 做确定性计算，不假装 Python 调用了模型。真实数据仅在授权的本地/企业环境处理；未获授权不得上传私有数据、顾客资料、订单号或合同。

## 1. 先检查输入，不急着写报告

```text
你是餐饮经营周报的编制助手。只使用我已授权提供的数据字典、数据质量报告和计算结果。
先回答：输入粒度、期间、门店和渠道范围是什么？履约订单和退款是否同群？
商家优惠、平台优惠、补贴、退款分别由谁承担？本次“贡献”遗漏哪些成本？
若缺值、重复冲突、期间不全或金额勾稽失败，列出阻塞，不补数据，不继续下结论。
不要猜测实际工具、模型、流程耗时、准确率或投资回报。
```

## 2. 用已计算结果起草（不要心算替换结果）

```text
依据 data_dictionary.md、quality_report.json、analysis.json 起草经营周报。
金额与比例以计算结果为唯一数值依据；不要将净收入写成银行到账/会计营收，或将所列成本后贡献写成完整净利润。
报告期和前周均写清日期。每项关键数字给出：文件 → 集合/筛选键 → 字段；保留源 record_id/CSV 行号。
结构：①数据集内事实 ②算术变动分解 ③可能解释/替代解释 ④待核事项 ⑤建议及验证边界。
相对变化和百分点严格区分；分母为零写未知。缺数据不补，无法定位来源就删去该断言。
前后周比较不能证明活动、广告或 AI 导致效果；不以模拟结果建议直接改真实经营系统。
写出最有力反例和会推翻建议的缺失信息。最后明确：本包模拟，未测得省时/准确率提升。
```

## 3. 与草稿分开做复核

```text
将草稿视为不可信文本，逐条抽取数字、期间、口径、来源定位和因果措辞。
对照计算输出逐条核对；列“原句 / 输出字段 / 核对值 / 是否一致 / 修改建议”。
若分析输出更新，旧草稿必须重审。区分代码自洽、原系统对账、人工复核和真实效果验证，不能互相替代。
用 review_checklist.md 检查；你不能冒充人工复核人的签字。
```

## 4. 最小输入包

只需数据字典、质量结果、聚合分析、必要的脱敏追溯键；不要默认为写一页周报上传所有原始顾客信息。是否可上传、用哪个模型/工具、保留多久由用户/企业授权决定。本次没有任何私有门店数据。
